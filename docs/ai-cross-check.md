# AI cross-check of the draft labels (blind, n=15)

> **This is NOT human verification.** A separate Claude Code session (labeller `claude`) labelled 15 devices blind, from the device name and firmware only. It is the same model family that helped draft the labels and the code, so the two share blind spots that this check cannot reveal. Some of its sources are third-party trackers or search excerpts, which it says in its notes. The draft ground truth stays unverified: `verified_by_a` / `verified_by_b` are untouched, and no label was changed.

Generated by `python eval/blind/cross_check.py report eval/blind/external/blind_ai_claude.csv` (no LLM calls). Source checks come from `eval/blind/external/source_checks.csv`, written by the `fetch` step (one request per distinct URL, 3 s apart).

## Lane agreement with the draft labels

- Percent agreement: **12/15 = 80%**
- Cohen's kappa: **0.68** (chance agreement p_e = 0.37); approximate 95% CI 0.36 to 1.00 using SE = sqrt(p_o(1-p_o) / (n(1-p_e)^2)) (McHugh 2012).
- **n = 15 is tiny.** McHugh suggests at least 30 comparisons; the CI is a large-sample approximation and is only a rough guide here. One device more or less in agreement moves percent agreement by about 7 points. Treat these numbers as a description of this sample, not an estimate of label quality.
- Lane counts, AI: patch 2, retire 9, fine 3, unknown 1; draft: patch 4, retire 7, fine 4, unknown 0.

## Caveats

- **Same-model-family cross-check.** The labeller is a Claude session; the draft labels and this code were also written with Claude. Agreement can come from a shared mistake, so a high number here is weak evidence. It can find disagreements worth a human's time; it cannot confirm a label.
- **Third-party sources.** Several AI notes say a date came from third-party trackers or search excerpts because the vendor page would not render (B01, B09, B11, B13).
- **Automatic source check is literal.** It looks for the dates, versions, CVE ids and quoted phrases from the AI's reason (and quoted phrases from its notes) in the page text, with common date spellings. A miss can mean the page says it differently, renders the text with JavaScript, or does not say it. A hit only means the string is on the page, not that the page says it about this model: the AI's own notes say B13's page is about the sibling USG60W and B12's is a D-Link Croatia page. The device's own firmware is not counted as a claim unless the reason names nothing else (B10). Pages that returned 401/403/429/5xx or almost no text are marked "needs human check in a browser" (0 in this run).
- **Not human verification.** Labels count as verified only with two human reviewers' initials (`docs/ai-and-teamwork.md`). This check does not change that.
